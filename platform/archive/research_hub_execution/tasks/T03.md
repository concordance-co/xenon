## Required outputs

Explicit local-scratch profile, local defaults under XENON_HOME, FileCatalog registration, resource-budget enforcement, locality/authoring amendments, and offline contract tests.

## Implementation sequence

1. Add opt-in local-scratch construction without changing existing shared-workflow defaults. Use XENON_HOME/pipelines_v2/artifacts and the existing FileCatalog root; do not select CompositeCatalog/Postgres through inherited xenon.toml defaults.
2. Set initial scratch ceilings: 64 examples, 256 input tokens/example, 32 generated tokens/example, 256 MiB new artifact payload, 600 seconds execution and 8 GiB process-memory budget. Named recipes may choose stricter limits; increases must be explicit in the saved spec. Model-cache downloads are a separate preparation step and budget.
3. Reject remote datasets, remote feature refs requiring localization, API explanation providers and cloud runners in this mode. Support a prepared offline model cache; a missing cache gives a preparation command, not an automatic network fallback.
4. Enforce row/token limits before execution, bytes while writing, and time/aggregate subprocess-tree RSS through a supervised worker with cleanup/checkpoint behavior. Estimates alone do not count as limits. Report non-enforceable device memory separately and fail unsupported strict combinations.
5. Update LOCALITY and workflow guidance with the bounded exception already requested by the user. Preserve production Modal activation locality and transfer policy. Ignore configurable in-repo output roots; do not commit data files.

## Verification and acceptance

- End-to-end toy workflow passes with Modal, Postgres and outbound network entry points made fatal, even with shared defaults configured.
- Each limit has an over-budget test that stops before committing a final result; wall-time and RSS have child-process tests, not only config assertions.
- Missing cache and remote-input requests fail clearly. Local run/artifact is discoverable through FileCatalog.
- Existing report-local and shared Modal workflows preserve their current behavior.

New `tests/pipelines_v2/runtime/test_local_scratch.py`; existing local runner/storage/config and path tests. Network sentinel includes the subprocess, not just the parent.
