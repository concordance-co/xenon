## Required outputs

New optional `pipelines_v2/engine/torch/` with serialized engine kind, GPT-2 adapter, finite capabilities, scoped hook/session lifecycle, gradient operation interface and runtime lock. Public exports/registry/dispatch and contract tests included. Add optional `GenerationSpec.target_token_ids` (default empty) and per-row `target_logprobs` for baseline and patched generation: log-softmax probabilities over the full vocabulary, read at the last unpadded prompt token before the first generated token, retaining only declared token IDs. Omit the new field/row payload when unused in both ordinary and semantic serialization so legacy hashes stay unchanged. Validate token IDs against the resolved vocabulary; advertise LOGPROBS only once this readout works. Specs with non-empty target_token_ids require a granular TARGET_LOGPROBS capability registered through T24; only TorchEngine advertises it until another engine implements the readout, so such specs bound to vLLM or toy engines fail at plan.

## Implementation sequence

1. Implement the existing engine protocol for GPT-2 with a resolved Hugging Face revision and tokenizer. Keep torch/transformers imports lazy. Freeze eager attention and FP32 CPU for correctness; do not advertise every Transformers architecture.
2. Implement prompt residual capture and generation respecting Example keys, attention masks, padding, token selectors, prompt/generation boundaries and existing feature payloads. Prompt-side edits are the first patch surface; reject unsupported generation-time edits.
3. Supported residual operators are exactly `InterchangePatch` (full-state donor replacement), `AddDirectionPatch`, and a new registered `ScalePatch` (`scale=0.0` ablates; `scale=1.0` is identity; scale must be finite). TorchEngine declares {interchange, add_direction, scale}; the existing vLLM and toy engines keep their current sets, so ScalePatch bound to them fails at plan. Other patch operators fail capability validation for this engine until separately qualified. Register through existing patch codecs plus T24 extension points. Validate donor model/site/shape/token alignment. A full-state replacement must not silently become a mean vector.
4. Expose an operation-scoped differentiable forward hook to downstream research operations, not `train()` on every engine. Freeze model weights; allow input/mask gradients. Use hooks that preserve autograd and always remove them after success, cancellation or exception.
5. Add a session lifecycle that can be reused by T06 with explicit state reset. CPU baseline first; report MPS unverified until its own numerical and hook checks pass. CUDA qualification belongs to T06.

## Verification and acceptance

- Random tiny GPT2Config fixture matches direct HF forward logits and selected residuals at FP32 rtol=1e-4, atol=1e-5; padding and reordered batches retain correct example/token identity.
- Declared target logprobs and their pairwise differences match a direct HF forward under the FP32 oracle tolerance; padding, target order and invalid token IDs are tested. No full-vocabulary arrays leak into rows.
- Identity patch equals baseline; forced tensor replacement equals an independently modified forward. Gradient finite-difference test uses a tiny deterministic model and frozen parameters.
- Hooks do not leak after failure; dropout disabled; no retained autograd graphs across requests. Memory does not grow across repeated bounded calls.
- New ScalePatch and nonempty target-token requests bound to vLLM/Toy fail during planning with a mocked submission sentinel proving no GPU worker is launched.
- Existing vLLM/Toy deserialization and tests pass without importing optional torch. T08 adds actual pretrained-model proof.

New `tests/pipelines_v2/engine/test_torch_engine.py`, `test_torch_hooks.py`, `test_torch_gradients.py`; existing engine contracts and execution oracles.
