## Required outputs

C03 journal/checkpoint and finalization helpers, coverage/integrity verifier, capture/intervention incremental persistence and resume, orphan final-manifest/catalog repair, failure-injection tests. Existing generation recovery retained.

## Implementation sequence

1. Define immutable batch/shard payloads and partial records separate from the canonical final manifest. Persist planned example/token/site coverage, payload checksums, operation semantic identity and shard layout. Use unique attempt temporary names and safe single-writer ownership; retries cannot race to overwrite valid payloads.
2. Commit payloads before a completion manifest; on Modal, establish volume commit visibility before catalog publication. Partial, killed, corrupt or short artifacts never publish completion. A valid manifest with a failed catalog update is recoverable idempotently.
3. Generalize incremental capture/intervention callbacks to journal completed units, preserving output order through stable keys. Resume verifies checksums and identity, computes missing coverage and processes it once. Do not infer completeness from directory existence or record status alone.
4. Teach orchestrator and reusable-step lookup to validate final completion, including recovery of running records. Legacy complete artifacts stay readable under explicit legacy policy; invalid old partials are not certified.
5. Provide extensible checkpoint payload references for learned optimizers/samplers/RNG (implemented by T10/T19 as applicable). If exact continuation is unavailable, declare restart-at-unit semantics and preserve completed independent units.

## Verification and acceptance

- Kill after payload write, after journal write, before manifest, after manifest but before catalog; each resume yields exactly the planned unique coverage or a clear integrity error.
- Corrupt/truncated chunks, changed spec/source/data/dtype, missing site coverage, duplicate keys and incompatible shard layout reject unsafe reuse.
- A running record plus partial payload never becomes completed. Two finalize attempts are idempotent or safely conflict.
- Existing generation failure/resume and cancellation tests remain green; zero-row legitimate work has an explicit complete representation.

New `tests/pipelines_v2/runtime/test_partial_recovery.py` and `tests/pipelines_v2/storage/test_finalization.py`; existing generation/runtime/workflow/cancel tests.
