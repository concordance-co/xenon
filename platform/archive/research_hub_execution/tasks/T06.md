## Implementation sequence

1. Define profile identity over resolved model/runtime/hardware topology/dtype/attention/hook/operation/shape/batch/compile settings and resource limits. Record measured loading/execution host RSS, GPU peak memory, elapsed time and declared headroom. Unknown model cells remain unverified.
2. Allocate one bounded worker, execute the real worst representative capture/intervention/backward path, persist the result, and release other shards only after the coordinator validates its exact profile. Fake success from an inference-only warmup cannot certify gradients.
3. On pass, let the same worker process its assigned useful partition; reserve/deduplicate calibration rows. Canary failure cancels queued work; deterministic config failure never triggers a repeated cold-start loop. Handle concurrent requests for the same profile with one qualification owner and visible pending state.
4. Generalize workflow_batch_key and _RemoteExecutionSession through conservative engine sessions. Include runtime env/lock, device, hook layout and mutable state rules. Reset all hooks, gradients, seeds and intervention buffers between operations; close on cancellation or idle budget expiry. External harnesses remain separate processes.
5. Qualify GPT-2 CPU versus one Modal CUDA device for generation/capture/patching; qualify vLLM reuse regressions on existing supported paths. Use the guide's preregistered FP32 rtol=1e-4/atol=1e-5 starting tolerance for direct reference comparison; investigate failures before scientific evaluation, and apply the documented calibration policy without retrospective widening.

## Verification and acceptance

- Fake scheduling proves zero fanout before persisted pass, no fanout after failure, one load for compatible operations, new load for incompatible state and exactly-once calibration row coverage.
- Profile changed in any workload/resource dimension misses qualification; estimated profile is never labeled measured. Model-parallel GPU count is distinct from shard count.
- Live bounded CUDA canary records peaks and one cold load, continues useful work, then survives a deliberate worker interruption through T05.
- Idle/cancel closes resources; transport retries are bounded and logged. A rejected batch adaptation never changes experimental semantics silently.

New `tests/pipelines_v2/runtime/test_qualification.py` and `test_torch_sessions.py`; fake scheduler and existing deployment/session tests. Live gate recorded separately with run IDs and allocation.

## Resource and external dependency limits
