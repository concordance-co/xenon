## Required outputs

First-class publication operation and receipt, payload/ref rewriting, hash verification, idempotent shared registration, local-to-remote lineage and docs.

## Implementation sequence

1. Accept a completed local artifact plus target store/catalog and explicit payload-byte ceiling. Validate integrity, permitted data class, semantic provenance and dependency closure. Publication is opt-in, never a side effect of local scratch.
2. Traverse only manifest-declared references; validate paths stay inside artifact roots, enumerate dependencies, upload immutable payloads to staged remote names via the client-side Modal volume upload API, verify hashes and rewrite every nested storage ref. Existing ModalVolumeStore writers assume a mounted volume; use a bounded CPU worker with that mount for final validation/manifest commit, not local calls to mounted writers.
3. Publish a new remote manifest whose scientific identity is unchanged and whose lineage names local source and publication operation. Persist data durably before final/catalog visibility; retries resume by content hash. Preserve local artifact.
4. Register through the existing shared catalog and FileCatalog mirror; recover if transfer finishes but indexing fails. Do not mistake published storage location for hardware requalification.
5. Document cases requiring recomputation: unresolved model provenance, unavailable payload dependencies or incompatible semantics. Shared production datasets still follow Neon conventions; do not upload arbitrary scratch files as datasets.

## Verification and acceptance

- Nested feature, label and input refs round-trip locally to a fake remote store with identical content hashes and no local-only paths in the remote manifest.
- Inject interrupted upload, mismatched checksum, missing dependency and failed catalog registration; retries are idempotent and never expose incomplete final records.
- One bounded live publication is readable through shared catalog and produces a local receipt. No model execution occurs during publication.
- Oversized/unknown provenance artifacts fail admission; original local artifact remains usable.

New `tests/pipelines_v2/storage/test_publication.py`; storage/catalog contracts and a separate opt-in live publication check.

## Resource and external dependency limits

Live proof publishes one small result artifact <=16 MiB, not an activation bank. Missing credentials leaves live verification pending with the exact failed operation.

A required inaccessible asset or unexecuted live gate leaves the task integration-pending. Complete independent implementation and deterministic tests, retain diagnostics, and name the exact remaining gate. Do not silently substitute a different model/evaluator or mark fixture tests as live qualification.
