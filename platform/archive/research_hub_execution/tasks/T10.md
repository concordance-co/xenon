## Required outputs

New external attribution operation/adapter under `operations/attribution/`, upstream/tool locks, versioned request/result JSON, safe subprocess driver, official-evaluator importer and fixture tests; C06 outputs. Add an `external_tool` runtime descriptor accepted by LocalRunner and Modal transport. It specifies control-runtime lock, tool interpreter/Python version, tool lock, pinned repository/submodule commits and entrypoint. On Modal, use the Xenon control interpreter plus a separate upstream tool venv/interpreter in the image; invoke the tool as a subprocess over C06 files. This preserves Python >=3.13 in control code while allowing upstream's own Python version. The tool environment does not import Xenon. T20/T23 reuse this runtime kind; T02's native runtime specs remain compatible.

## Implementation sequence

1. Inspect the official repository and paper linked in SOURCES.md at implementation time. Resolve repository commit and every MIB fork/submodule commit. Record entrypoint, task config and installed package inventory; do not invent a historical SHA. Use upstream Python version in a separate venv/container if different from Xenon's >=3.13.
2. Define the file-based external-tool boundary: immutable request, input refs, working directory, progress/exit status, raw upstream outputs, normalized result. The subprocess need not import Xenon. Pass an argument vector, not shell-evaluated commands. Bound time/output disk and terminate the whole process group on cancel. Local and Modal builders provision the pinned checkout/submodules and both required locks before execution, with separate import checks. Batch/session resolution keeps external-tool runs separate from native engine processes. Measure subprocess-tree RSS and relevant GPU memory for C02 qualification; never certify mask fitting from the control process memory alone.
3. Start with GPT-2 IOI node attribution and official evaluation; preserve base/source orientation, basis and input-node coverage, optimization/sparsity schedule and splits. Record unsupported options explicitly. No inference API is assumed to support backward.
4. Import task-specific node IDs, mask/ranking scores and curve points with units/metric definitions. Reject missing/duplicate nodes, nonfinite results, inconsistent k/coverage and wrong model/evaluator identity. Save raw evidence for debugging.
5. Expose upstream checkpoint resume only if optimizer/sampler/RNG/schedule state truly resumes. Otherwise restart the unfinished method/seed unit and preserve completed units; do not label it step-exact continuation. Checkpoint integrity uses C03.
