## Required outputs

Minimal internal registration interfaces for engines, operation loaders/executors, feature storage and site codecs; explicit new-site kinds with legacy fallback; golden existing payload/hash fixtures and import-light dispatch contract.

## Implementation sequence

1. Before changing codecs, capture representative serialized specs and spec/semantic hashes for every existing registered family, including sparse/default cases. Fixtures must include generation, capture, patching, reports and workspace-specific lazy registrations.
2. Introduce narrowly scoped registration points only where needed by multiple new tasks. Preserve existing built-ins and error behavior. Register operation loader, execution placement and output artifact kind together so local/remote routing cannot disagree.
3. Capture sites currently discriminate by `site`/`record` key presence; add explicit kind for new sites while reading old payloads unchanged. New optional fields on existing specs are omitted when default/unset in legacy serialization and semantics. Intentional scientific invalidation must be explicit and tested, not incidental field addition.
4. Feature formats currently default unknown kinds to JSON. Register tensor-capable feature codecs and reject unknown dense formats; do not serialize neuron/latent banks as giant JSON. Keep old residual/MoE round-trips exact.
5. Ensure registry lookup/import does not import torch, Transformers, Diffusers, plotting or external tools. Add a small test-only third engine/operation/site that round-trips and dispatches without modifying shared switch lists. Fail duplicate/conflicting registrations deterministically.

## Verification and acceptance

- Golden legacy payloads/hashes unchanged unless an explicitly documented bugfix requires intentional invalidation. Old workflow snapshots load successfully.
- New test-only engine/site/feature/operation travels plan → serialize → deserialize → local/fake-remote execute → typed artifact.
- Optional dependency import sentinels stay silent in CLI plan/core import. Unknown dense feature kinds fail clearly rather than becoming JSON.
- Existing engine/operation/storage/runtime contracts pass; extension registries do not enable arbitrary executable module paths from untrusted serialized specs.

New `tests/pipelines_v2/test_extension_registration.py`, `test_legacy_serialization.py`; existing serialization/engine/storage/execution contracts.
