# Prompt Confusion Phase 04 Design

## Goal

Phase 04 is a small reset, not a scale-up.

The objective is to test whether we can build a clearer prompt-confusion
benchmark that:

- is easy to hand-audit
- makes `STRATEGY` and `SETTINGS` roles explicit to the model
- reduces sentiment-heavy wording
- is small enough to iterate quickly
- defaults to prompt-only capture for the first mechanistic pass

## Core changes from Phase 03

1. Smaller dataset
   - target size: `288` rows
   - this is large enough for first-pass splits but small enough to inspect

2. More explicit system prompt
   - the system prompt now explains:
     - what `STRATEGY` means
     - what `SETTINGS` mean
     - that both should be considered
     - that settings constrain execution when they disagree with strategy

3. More neutral phrasing
   - avoid highly affective words like:
     - aggressive
     - degen
     - churn
     - safe
   - replace them with more operational wording about:
     - size tier
     - entry frequency
     - execution allowance
     - waiting preference

4. Prompt-only workflow default
   - `capture_generation = false`
   - initial capture should not mix prompt activations with generated output

## Families

Phase 04 keeps only four families:

- `trade_size_force_large`
- `trade_size_force_small`
- `activity_force_trade`
- `activity_force_observe`

That is enough to test:

- size conflict
- action conflict
- opposite semantic directions within each live dimension

## Row count

The generator uses:

- `4` families
- `2` strategy variants per family
- `2` setting phrasing families per family
- `3` environment pressure buckets
- `3` context variants per pressure bucket
- `2` pair members (`aligned`, `strong_conflict`)

Total:

`4 x 2 x 2 x 3 x 3 x 2 = 288 rows`

## Expected use

Phase 04 should be used in this order:

1. inspect generated JSONL and prompts by eye
2. upload to Neon
3. publish the workflow dataset relation
4. run prompt-only capture
5. do first-pass probe sanity

Only after that should we decide whether:

- the dataset should be scaled up
- more families should be added
- or a behavioral generation run is warranted
