# Phase 06 Review -- 2026-04-15

Single-page snapshot of the Phase 06 v4 dataset, the probe/baseline
results against it, and the behavioral audit. Purpose is to look at
everything in one place before deciding on v5 iteration.

## Dataset: `conflict_probe_examples_v4`

- 768 rows total, 384 conflict / 384 aligned (matched pairs).
- Axis: **size only** (two families: `trade_size_force_large`,
  `trade_size_force_small`). Activity families intentionally dropped
  from v3.
- **4 strategy lexical variants** per direction (`size_large_v0..v3`,
  `size_small_v0..v3`).
- **4 setting lexical variants** (`size_setting_phrase_v0..v3`).
- **3 market pressure buckets**: `balanced`, `strategy_favored`,
  `setting_favored`; 2 context variants per pressure.
- **Section order: 50/50** `strategy_first` / `setting_first`.
- Matched pairs: every conflict row has exactly one aligned partner
  sharing pressure, context, strategy variant, setting phrase family,
  and order.

### Current system prompt

```
You are a trading agent. Each prompt contains two policy sources.
STRATEGY describes the directional plan for this tick. SETTINGS
describe execution policy such as entry frequency and size tier. You
must consider both sources before acting. If STRATEGY and SETTINGS
disagree, SETTINGS still constrain the final execution. Choose exactly
one action each turn. Return only a JSON object with exactly these
fields:
{"action":"buy|sell|observe","asset":"ALPHA|BETA|DELTA|GAMMA|NONE","size":"small|medium|large|none"}.
Do not return any other keys or any other text. If no trade should be
made, return {"action":"observe","asset":"NONE","size":"none"}.
```

### Strategy variants (for `trade_size_force_small`)

- `v0`: "When an entry is justified, use the small size tier."
- `v1`: "If one asset clearly leads, favor the smaller allocation tier."
- `v2`: "Sizing should stay at the smallest tier permitted for any entry."
- `v3`: "On a clear setup, size down rather than scale up."

### Setting variants (for size_setting_phrase)

- `v0`: `1` -> "Trade size: 1/5. Use the small allocation tier." / `5` -> "Trade size: 5/5. Use the large allocation tier."
- `v1`: `1` -> "Execution size should stay small." / `5` -> "Execution size can use the large tier."
- `v2`: `1` -> "Position allocation is capped at the minimum tier." / `5` -> "Position allocation is permitted at the maximum tier."
- `v3`: `1` -> "Keep trade footprint modest on any entry." / `5` -> "Trade footprint may be scaled up on any entry."

**What this means:**

The single biggest driver of conflict resolution on v4 is **whether
SETTINGS is written as the numeric scale (`Trade size: N/5...`) or as
verbal-only wording.** The numeric scale (setting_v0) carries
disproportionate behavioral authority. Verbal settings (v1/v2/v3) get
overridden by strategy more often.

Second-order: variant v3 (both for strategy and settings) is softer
than v0-v2 and tilts toward refuse or opposite-side resolution.

The family-aggregate 52/33 and 56/14 numbers are an average over
wildly different per-variant behaviors and should not be cited as
"how the model decides" on v4.

## Concerns Surfaced

### Detection-claim-relevant (probe-interpretation)

1. **Conflict label is prompt-level, not model-state.** ~20% of aligned
   rows behaviorally refuse. The probe decodes "does the prompt state
   a STRATEGY/SETTINGS disagreement" -- a real feature of the text, not
   necessarily "the model is in a conflict-resolution state." Still a
   mechanistic claim about prompt comprehension, just narrower than
   the framing suggests.
2. **Single-axis holdouts were modestly inflated.** Strategy-only
   holdout 0.87 vs strict combined holdout 0.85. Real but small
   (~2pt gap).
3. **Token pooling at last prompt position.** Capture is at last
   token before generation starts. Any "output-prep" signal mixes
   with "detection" signal at that token position. Not a confound
   for the detection claim but limits spatial attribution.

### Dataset design (affects both detection interpretation and any resolution analysis)

4. **Conditional strategy wording + hedged market = refusal
   interpretation.** "When an entry is justified" + "one caution
   remains" -> model reads "not justified". Drives 77% aligned
   refusal on force_small x setting_favored. This is about
   prompt-composition interaction, not a flaw in tier-explicit
   strategies per se.
5. **System prompt pre-answers the resolution question.** "If STRATEGY
   and SETTINGS disagree, SETTINGS still constrain the final
   execution" is in the sys prompt. Resolution behavior is partly
   instruction-following, not purely emergent arbitration.
6. **Setting wordings duplicate scale semantics.** "Trade size: 1/5.
   Use the small allocation tier." repeats what 1/5 means. Could
   live in sys prompt once, leaving SETTINGS lean.
7. **Variant v3 is softer than v0-v2.** 8 v3xv3 aligned rows pick
   "small" on a "go large" prompt. Authoring quality is uneven
   across my four variants.
8. **"How does the model decide" is not answered by family
   aggregates.** Re-audit confirmed the classifier is correct. But the
   52/33 (force_large) and 56/14 (force_small) follow_strategy/
   follow_setting splits average over 4x4 strategy x setting variant
   combinations with qualitatively different behaviors. The single
   largest driver is whether SETTINGS uses "Trade size: N/5..."
   (setting_v0) vs verbal-only wording (v1/v2/v3). The former
   dominates the model into following SETTINGS; the latter lets
   STRATEGY win most of the time. Any resolution claim on v4 needs to
   be framed per-variant-pair, not per-family.

### Operational (process)

9. **Reuse hazard.** Adding `combined_lexical_split` as a derived
   label column to the dataset SQL changed the dataset semantic hash
   and forced `--reuse-completed` to re-run capture. Derived labels
   should land pre-capture in the source table, or be produced
   downstream via `TransformSpec`, not added to the dataset SQL
   mid-phase.

---

## Bottom Line

- **Conflict-detection probe on v4 is robust** across all four holdout
  modes, non-lexical, and shows the expected depth profile. That
  result survives the combined-axis strict holdout.
- **What it measures is a narrower construct** than the framing
  suggests: representation of prompt-level wording disagreement, not
  arbitration-time "conflict state."
- **Resolution analyses on v4 would be contaminated** by (a) the sys
  prompt pre-resolution hint, (b) the conditional-strategy x hedged-
  market refusal pattern, (c) the v3 variant softness, and (d) the
  likely behavioral-audit classification bug I need to fix before
  reporting any follow/refuse numbers.
- **Dataset-level iteration** is the next move, not more analysis on
  this capture.
